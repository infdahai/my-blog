## 二 · ManuFacet 在版图中的位置（并入说明）

### 2.1 为什么单开哲学 D，而不是塞进 A
| 维度 | A 智元/OpenX/π | **D ManuFacet** |
|---|---|---|
| 任务宽度 | 广（百～千任务） | 窄而深（亚毫米装配族） |
| 成功判据 | 任务完成/泛化 | **公差 + 接触力包络 + 恢复** |
| 力/触 | 可选扩展 | **协议级强制（每帧 wrench）** |
| 时序标注 | sub-step / 技能 | **接触相 taxonomy（7 相）** |
| 失败策略 | 常过滤 | **保留 + 飞轮回流** |
| 跨本体 | 多源拼盘或共训 | **少本体 + 同一 13-D schema** |
| 典型上限 | 桌面/家务/通用操作 | **±0.5 mm 插入/座装** |

→ **A 解决“会不会干很多事”；D 解决“在接触里能不能稳、准、可恢复”。** 混称“真机数据”会掩盖精密制造的真实瓶颈（站页：Scaling ≠ precision）。

### 2.2 与 B/C/E 的关系
- **vs B（光轮/它石）**：EGO/人数据无亚毫米 wrench 真值；WIYH 有触觉但任务域是人中心 VLTA，不是产线公差装配。D 与 B **正交互补**，不是替代。
- **vs C（NVIDIA）**：仿真可造力，但接触 sim2real 是深坑；ManuFacet 选择**真机力同步**作为精密域主供给。C 可作覆盖/危险工况乘数，不能默认等于 D。
- **vs E（HRDexDB）**：E 是小而精的配对金标准；D 是 **1000h 工业量级** 的力同步语料。E 校准上限，D 提供可 soft 的规模。

### 2.3 产业角色一句话
**Data Foundry / ManuFacet = 工业接触数据的“协议制定者候选人”**：谁定义力同步 schema + 接触相 + 失败保留，谁就在精密制造具身里定义接口（类比 OpenX 曾在通用操作里定义跨机构格式）。

## 三 · 版图 × 数据集路线（R1–R6）映射

```
R1 EGO/人数据  ←── 光轮 EgoSuite · 它石 WIYH · EgoVerse/Open-AoE · EgoInfinity
R2 UMI/接口    ←── Koala/YUBI/相机中心 (版图中企业公开较少,偏学术)
R3 仿真合成    ←── NVIDIA GR00T/Cosmos · 智元 Digital World
R4 真机遥操    ←── 智元 World · π · OpenX          ╲
                 └── **ManuFacet (D) 精密分支**  ─── 与 R6 强耦合
R5 统一动作空间 ←── OpenX 格式 · π · UCAG-P；**D 要求扩展 wrench 通道**
R6 物理/接触   ←── 它石 VLTA · HRDexDB · CHORD · **ManuFacet F/T+接触相**
```

**研究含义（洞察，非实跑待办）**：
1. 读通用真机论文时，先问：是 **A 还是 D**？有无 sync F/T、接触相、失败保留？
2. 读 EGO/企业人数据时，明确 **到不了 D 的物理层**——价值在规模与语义，不在亚毫米力。
3. R5「统一动作空间」若目标含精密装配，**坐标锚必须能挂 wrench/接触相**，否则只统一了“空气中的位姿”。
4. 版图上的“开源生态争夺”现为三线：通用真机格式(A) · 人/EGO 规模(B) · **工业力协议(D)**；仿真(C)是第四线基础设施。

## 五 · 一句话口径（版图统一引用）
